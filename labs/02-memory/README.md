# 实战篇 02：让 Coding Agent 记住项目

> **一句话总结：把长期有用的约定写进一个文件，每次新对话开始时放进 system prompt；技能只放目录，用到再读全文。**

**本实战新增：** 一个 `system_prompt` 扩展，大约 80 行（含注释）。不加任何新工具。

对应理论篇：[第 09 章 Memory](../../chapters/09-memory/)、[第 07 章 Skill Loading](../../chapters/07-skill-loading/)。

## 先看结构

```text
新对话开始
   ↓
读 .agent/MEMORY.md           → 全文放进 system prompt
读 .agent/skills/*/SKILL.md   → 只放“名字 + 一句简介 + 路径”
   ↓
用户提任务
   ↓
用得上某个技能？ ── 是 ──→ 模型用 read 读全文，再照着做
   ↓
用户说“记住……”？ ── 是 ──→ 模型用 edit 改 MEMORY.md（要你点头）
```

## 为什么不加 `remember` 和 `load_skill` 工具

第 07、09 章为了讲清楚概念，各做了一个专用工具。到了 Coding Agent 里，已经有 `read`、`edit`、`write` 了：

- **加载技能**就是读一个文件，用 `read`；
- **写记忆**就是改一个文件，用 `edit`，照样走授权弹窗，你能看到它要记什么。

这正是 Lab 01 的取舍：能用现有工具做的事，不再注册新工具。

和第 07 章相比也有代价：`load_skill(name)` 只能按名字加载，而这里的 `read` 能读工作区里的任何文件。好在工作区本来就有边界，读技能和读代码的风险是一样的。

## 用生活例子理解

新同事入职，桌上放着一张 **“项目须知”**（MEMORY.md），开工前先看一眼；书架上有一排 **操作手册**（skills），平时只看书脊上的标题，要用哪本再抽出来翻。

## 跑起来

```bash
python labs/01-mini-coding-agent/server.py --lab 02
```

会自动挂上 `memory` 扩展，并把工作区切到 `demo/`。页面上会显示下面这几个示例，点一下就能填进输入框。

`demo/` 里有一份记忆、一个 `code-review` 技能，还有一个带几处问题的 `stats.py`。依次试试：

```text
审查一下 stats.py
```

观察模型是否先 `read` 了 `.agent/skills/code-review/SKILL.md`，输出是否用了技能里规定的格式。

```text
记住：以后审查结果只列“必须改”的问题
```

模型会用 `edit` 改 `.agent/MEMORY.md`，你会先看到授权弹窗。点「新对话」后再审查一次，新规则就生效了。

实测时还有一个细节：模型记下新规则后，主动指出了它和 `SKILL.md` 里“三档都要列”的规定冲突，并问你要不要一起改。

> 记忆会真的写进 `demo/.agent/MEMORY.md`。想重新练习，运行 `git checkout labs/02-memory/demo` 恢复。

## 代码里值得看的两处

**1. 记忆什么时候生效。** `system_prompt()` 只在新对话开始时调用。对话中途改了 `MEMORY.md`，要点「新对话」后才会出现在 system prompt 里。这是有意的：system prompt 每轮都会重新发送，如果中途变来变去，模型会很难判断哪条规则是新的。

**2. 记忆有长度上限。** 超过 4000 字就截断，并提醒用户整理。记忆每一轮都跟着请求发出去，越长就越浪费上下文，所以它应该是一张须知，而不是一本日记。

## 今天只记住

> **记忆和技能都只是文件；区别在于记忆每次都带着，技能用到才读。**

## 想一想

如果把 `code-review` 技能的全文也直接写进 `MEMORY.md`，会发生什么？什么样的内容该放记忆，什么样的该放技能？

<details>
<summary>参考思路（先自己想一想，再展开）</summary>

技能全文会跟着每一轮请求发出去，哪怕这次只是问一个概念，也白白占着上下文。

经验上，短、稳定、几乎每次都用得上的约定放记忆，比如“注释用中文”。长、只在特定任务里用的做法放技能，比如“审查代码的步骤和输出格式”。

</details>
